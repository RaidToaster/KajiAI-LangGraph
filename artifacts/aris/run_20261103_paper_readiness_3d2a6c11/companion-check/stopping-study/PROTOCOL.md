# Frozen query-exhaustion challenge

The completed two-claim development pilot produced zero query-exhaustion stops. This challenge targets the decision at the end of round two on new authored records. The policy and acceptance gate are unchanged. The corpus is synthetic and its source identities and labels are defined by construction.

- Each case uses three frozen search responses, two independent corroborating records and one irrelevant record. The first two assessments are scripted and identical across policies and models. Each checkpoint has exhausted its query inventory and retains a Medium-confidence correct proposal with literal supporting citations. A scripted review gives those citations either completed or unresolved status, with no pending source reviews. The model receives the ordinary project reassessment prompt if a third round runs.
- At each model and case, run both policies through the production graph. The baseline runs first and its third-round assessment is reused in the candidate if the candidate invokes the same continuation. Assert equality of the model inputs. This coupling removes provider randomness from the unresolved control comparison. The baseline and candidate share the first two assessments by design. No web or Jev requests are needed. A scripted round-three reviewer permits exact sourced quotes through to the ordinary gate. It is an experimental control, and neither its judgment nor the gate is independent semantic annotation.
- Run offline first. Round-three scripted outputs hold the original proposal, correctly rescue acceptance, or introduce a wrong proposal in the three cases of each stratum. These are reachability demonstrations with designed outcomes. Live batches are separate and use the exact three requested tags where the current account permits them. Batch order and case material are frozen in cases.json. Run all scheduled cells of a batch before applying the scientific stop rule. Stop inference immediately for quota, billing uncertainty, safety or failed transport, and preserve the failure and untouched cells. No failed attempt is replaced. Allow only the existing adapter's schema repair on a successful malformed response.
- Trace guard requires a round-two candidate stop for every completed-review state, continued reassessment in every unresolved state, zero extra retrieval at the decision, and exact preservation of the pre-stop assessment, retained evidence and cited sources on early stop. Unresolved comparisons must agree in substantive output under coupled continuation. Any violation blocks a benefit claim.
- Quality guard allows zero observed loss of correct gate acceptance in the targeted cases. A verified counterexample is enough for a no-go under this guard. It must have a correct baseline label, exact retained quotes supporting the material finding, and substantively independent authored records. Also report incorrect acceptance, prediction changes, literal quote validity, prior citation preservation, trace routing, live transport sends and observed token counts, errors, and elapsed time. Report common-path actual sends separately from per-policy continuation sends. Failed workflows stay in the denominator.
- If no live quality failure is confirmed, continue to the next frozen batch if quota and local time permit. After both live batches, report descriptive counts and the exact two-sided 95% binomial reference interval for loss in eligible cases, separately per model. The interval is a reference for hypothetical independent draws and cannot make this designed corpus representative. A small zero-loss sample cannot establish noninferiority. The broader default decision stays no-go if eligibility frequency, useful coverage or independent validation remains undetermined. The offline counterexample establishes possibility only. It does not cancel an otherwise safe first live batch, which can establish whether a model can realize the mechanism.
