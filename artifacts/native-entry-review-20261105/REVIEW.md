## Decision

**A new, strictly bounded native actual-record diagnostic is justified. Its successful outcome may justify entering the original development screen even if both models honestly abstain on Graham. It cannot turn any synthetic phase into a pass or establish acceptance utility.**

There is a specific engineering premise: the old native Graham result failed because findings imported details from other passages, titles, and incomplete text. The current complete-paragraph catalogue and explicit component namespaces directly address that demonstrated failure, but the current combined implementation has not yet faced the actual native Graham path. The latest synthetic decision has valid references and faithful narrow findings, yet explicitly reduces confidence because its records are authored fixtures and contradicts itself about independence. This makes mismatch between the conditional fixture task and the real-record task a plausible diagnostic hypothesis. It is not evidence that the implementation works on authentic records, nor an excuse for the failed utility requirement.

The proposed actual-record test changes both the task context and the entry rule after observing failures. Disclose that selection. Call the new outcome a **native fidelity diagnostic**, not a pass of the earlier utility/safety readiness rule. The old A/B High requirement was real, was not met, and must remain failed. Replacing it with another repeated authored-control wording exercise has little demonstrated value now.

Requiring Graham itself to become accepted would be a poor new entry condition. Its shared tweet lineage, missing primary authentication, snippet-only records, and documented source cross-reference make conservative provenance abstention plausible under the unchanged gate. Forcing a positive would select for clearing those uncertainties. Requiring some extra, searched-for real acceptance per model before the mandatory screen would also introduce another adaptively selected sample and extra calls. The original eight-case screen is already the predeclared place to ask whether correct supported acceptance increases. A clean native fidelity result is sufficient engineering premise to spend that bounded screen; it is not evidence of possible gain beyond the mechanism hypothesis.

## What the code gets right, and its limits

The catalogue copies intact client-created ranges; unknown IDs become blocking gaps. The downstream origin conversion checks that anchors belong to their stated source. Required C0 strings remain client-owned. The explicit class-to-boolean mapping records the model's adjudication rather than deriving it from confidence, source counts or a global proposal; a C0/global-label mismatch blocks. The raw explicit classes/rationales, selection ledger, original visible records, literal ranges, date contexts, and declared material questions survive. Unknown/missing components and adverse questions do not disappear because their source is uncited. These are appropriate engineering safeguards.

The generated schema enums guide the cloud model; they are not enforced decoding and do not remove local binding checks. Catalogue coverage includes complete short paragraphs and selected intact ranges, not arbitrary paragraph combinations. Original visible records remain available. The underlying exposure is still the ranked twelve-source/3,500-character representation, which keeps complete paragraphs at the boundary; do not describe it as every byte of every originally retrieved document. If necessary context is outside that representation, preserve the limitation instead of importing it from memory, a title, or the checker's broader context.

The deterministic gate correctly retains declared gaps/contradictions, requires High, exact quotes, at least two hosts, resolved/cited assertions, actual counterevidence and independence flags, and both stances for CONFLICTING. These checks do not prove semantic support or provenance. I checked their downstream compiler dependencies as well as the four requested source modules.

There is an observed checker scope problem, not a hypothetical one: `graph.check_evidence` sends each exact quote plus up to 1,200 surrounding characters to Jev, and `jev.check_citations` asks about that context. The provenance check receives the same finding/context bundles and runs only if structural/citation gaps are absent. Its question asks for independent paths and does not simply trust outlet diversity, which is correct. Nevertheless, broader context can validate a finding unsupported by its chosen passage, and repeated source conclusions or the model's own independence wording can create apparent corroboration. Retain the existing checks, but a research-agent selected-passage and original-source lineage audit must separately reject such cases. Jev .80 is a necessary original criterion, not an independent truth certificate or a substitute for whole-claim support.
