Literal origin/action fields address observed incorrect metadata, rather than a desire for more High answers. Their utility must be tested prospectively, with no adjustment after the next output.

## Safe explicit component contract

Use an optional candidate-specific component row with an exact client-bound ID, a required enum `supported | refuted | conflicting | insufficient`, bare finding IDs, retained question IDs/material questions, and a short rationale when needed to explain the relation. C0 continues to name the exact original whole claim; other required strings and qualifications remain client-owned. Do not change the historical standard analyzer request schema or default mode.

The meanings must be fixed before dispatch:

- `supported` and `refuted` adjudicate the exact component on the supplied evidence, rather than merely documenting that somebody asserted it. Attribution-only targets are judged at their actual attribution scope.
- `conflicting` means supported observations genuinely oppose that same component, with target/date/population/measurement alignment explained. It does not mean two hosts differ, or merely that evidence is missing. Each side needs actual linked evidence; an unsupported stance tag is insufficient.
- `insufficient` means the component has not been adjudicated as any of the preceding three classes. Identifying that evidence is insufficient is not the original meaning of component resolution.

The compiler may encode explicit `supported/refuted/conflicting` as the old `resolved=true`, and explicit `insufficient` as `resolved=false`. This is a deterministic representation mapping of the model's own per-component adjudication, not semantic inference from IDs, a global verdict, number of findings, numeric thresholds or absence of gaps. Retain the original enum/rationale and mapping in the saved ledger and raw assessment. Technically the boolean projection loses class detail; the *stored assessment* remains lossless only because the enum survives. Do not call the boolean alone lossless.

Do not accept a second independently supplied boolean that can disagree with the enum. Missing/unknown enum, missing/duplicate required component, unknown/duplicate finding ID, invalid reference, or a contradictory explicit state must fail parsing or add a blocking contract gap. Keep all available raw judgments. The C0 enum must agree with the global proposed class: supported/TRUE, refuted/FALSE, conflicting/CONFLICTING, insufficient/NOT_ENOUGH_EVIDENCE. A mismatch must add a blocking consistency gap and retain both values; the client must not choose which one was intended. This check is justified because C0 is the exact whole claim. Do not require every subcomponent's class to equal the whole-claim label or infer the whole label from subcomponents.

Every declared top-level gap/contradiction and every component/origin material question continues to block, including when the enum says adjudicated. An enum never suppresses the conservative union. A declaration that the component remains unadjudicated contradicts an adjudicated enum and fails semantic readiness even if the union safely blocks acceptance. A concise conservative limitation need not contradict an adjudicated evidentiary class: distinguishing those is a model judgment audited against the exact target, not a compiler materiality classifier. Unknown prose inconsistencies must never be automatically cleared or converted into High. No automatic Jev materiality filter is justified.

Keep confidence, source independence, actual counterevidence trace and all other policy judgments explicit and unchanged. `conflicting` does not force High or guarantee acceptance. The existing gate still requires both stances, all assertions, two source hosts and lineage checks, literal quotes, qualifying Jev citation checks at 0.80 and the existing independent-provenance policy. An enum does not certify any of those conditions.

## Minimal literal provenance contract

Replace the candidate's free-written underlying-origin and source-action captions with optional selected literal ranges, separately named for underlying record/origin, **source-reported verification action**, event/data time and publication time. A source ID plus ordered inclusive local paragraph IDs, using the existing contiguous 250-word range machinery, is sufficient. Copy the quote from the supplied version into the stored ledger; do not ask the model to rewrite it. Unknown optional evidence remains absent/empty. An explicit “did not independently verify” passage is useful evidence and must survive as such; absence of an action passage does not mean the source performed no action.

This does not require another service call, a new framework or a new semantic classifier. Reuse a small range-expansion routine and the existing source lookup. Check source/range identity, order, full intervening text, word bound and serialization. Validate every selected range, including uncited/adverse origin rows. Invalid supplied references block; they must not silently become unknown. Preserve all origin material questions even when the corresponding source is absent from final findings.

If downstream code still expects string captions, those candidate strings can contain the copied quotes while the richer role/reference/quote records remain saved. They must not contain added adjectives or claims such as the model checking P1. Avoid a redundant free paraphrase that recreates the observed failure. For dates, retain the literal date evidence at its actual precision. Do not require normalized exact dates or infer an event date from a publication date; if normalized values are retained, they require an explicit role-supported link and audit. A quote can mention several dates without establishing which one is the measurement period.

Literal validity is not role validity. A perfectly copied passage about the model's input review does not establish a source's verification action; a transcript date does not establish the unemployment measurement period; two copied “independent” statements do not automatically prove independence on the target. The final model judgment, unchanged Jev review and full support/lineage audit remain necessary. Literalizing these fields prevents invented wording, not all provenance mistakes. The Kamra post's missing referent attachment cannot acquire complete support/independence credit through this representation.
